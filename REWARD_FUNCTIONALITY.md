# Reward System - Complete Functionality Documentation

## Overview
The reward system is a comprehensive gamification feature that allows users to earn, track, and redeem rewards through various activities. It includes multiple reward types, a coin-based currency system, a reward catalog for redemption, and transaction management.

---

## 1. Reward Types

### 1.1 RewardType Enum
Defines the different types of rewards users can earn:

- **POINTS**: Accumulatable points that can be used for various purposes
- **BADGE**: Achievement badges for milestones
- **COUPON**: Discount coupons
- **TROPHY**: Trophy/medal rewards for achievements
- **CUSTOM**: Custom reward types for special cases

### 1.2 RewardSource Enum
Tracks where rewards originated from:

- **CHALLENGE_WIN**: Won a challenge (rank-based rewards)
- **CHALLENGE_PARTICIPATION**: Participated in a challenge
- **DAILY_LOGIN**: Daily login streak rewards
- **STREAK_MILESTONE**: Reached a streak milestone (7, 30, 100, 365 days)
- **REFERRAL**: Referred a friend
- **ACHIEVEMENT**: Completed an achievement
- **ADMIN_GRANT**: Admin manually granted reward
- **OTHER**: Other activities

## 2. Core Reward Operations

### 2.1 Create Reward
**Function**: `createReward()`
- Creates a new reward for a user
- Validates reward type and source
- Stores reward metadata, challenge info, and rank (if applicable)
- Returns the created reward ID

**Use Cases**:
- System-generated rewards (challenge wins, daily login, streaks)
- Achievement unlocks
- **Note**: Admins cannot create rewards directly for users. Rewards are automatically generated by the system based on user activities.

### 2.2 Get User Rewards
**Function**: `getUserRewards()`
- Retrieves all rewards for a user
- Supports filtering by:
  - Reward type (POINTS, BADGE, COUPON, TROPHY, CUSTOM)
  - Reward source (CHALLENGE_WIN, DAILY_LOGIN, etc.)
  - Claimed status (claimed/unclaimed)
- Supports pagination (limit/offset)
- Returns rewards sorted by earned date (newest first)

**Response Includes**:
- List of rewards
- Total points
- Total badges count
- Total trophies count
- Unclaimed rewards count

### 2.3 Get Reward Summary
**Function**: `getRewardSummary()`
- Provides a quick overview of user's reward status
- Returns:
  - Total points accumulated
  - Total badges earned
  - Total trophies earned
  - Total coupons earned
  - Unclaimed rewards count
  - Recent rewards (last 10)

### 2.4 Claim Reward
**Function**: `claimReward()`
- Marks a reward as claimed
- Validates:
  - Reward exists
  - Reward belongs to the user
  - Reward is not already claimed
- Updates `isClaimed` flag and `claimedAt` timestamp

### 2.5 Get Reward by ID
**Function**: `getRewardById()`
- Retrieves a specific reward by its ID
- Returns full reward details including metadata

### 2.6 Get Rewards by Challenge
**Function**: `getRewardsByChallenge()`
- Retrieves all rewards associated with a specific challenge
- Sorted by rank (ascending)
- Useful for viewing challenge leaderboard rewards

### 2.7 Batch Create Rewards
**Function**: `batchCreateRewards()`
- Creates multiple rewards in a single transaction
- Used for awarding rewards to multiple users (e.g., challenge winners)
- Ensures atomicity (all or nothing)

### 2.8 Check Challenge Reward
**Function**: `hasChallengeReward()`
- Checks if a user already has a reward for a specific challenge and rank
- Prevents duplicate rewards
- Used before awarding challenge rewards

## 3. Challenge Reward System

### 3.1 Award Challenge Rewards
**Function**: `awardChallengeRewards()`
- Awards rewards to top N participants in a challenge
- Handles tie-breaking (users with same duration share the same rank)
- Point distribution:
  - Rank 1: 1000 points
  - Rank 2: 500 points
  - Rank 3: 250 points
  - Rank 4+: 100 points
- Prevents duplicate rewards for the same challenge/rank
- Creates rewards with:
  - Type: POINTS
  - Source: CHALLENGE_WIN
  - Challenge ID and title
  - Rank achieved

### 3.2 Award Challenge Participation Reward
**Function**: `awardChallengeParticipationReward()`
- Awards participation points when a user joins a challenge
- Amount: 50 points
- Prevents duplicate participation rewards
- Creates reward with:
  - Type: POINTS
  - Source: CHALLENGE_PARTICIPATION
  - Challenge ID and title

## 4. Daily Login & Streak Rewards

### 4.1 Award Daily Login Reward
**Function**: `awardDailyLoginReward()`
- Awards points based on login streak:
  - 1 day: 10 points
  - 7+ days: 50 points
  - 30+ days: 100 points
- Creates reward with:
  - Type: POINTS
  - Source: DAILY_LOGIN

### 4.2 Award Streak Milestone Reward
**Function**: `awardStreakMilestoneReward()`
- Awards badges for streak milestones:
  - 7 days: 100 points (BADGE)
  - 30 days: 500 points (BADGE)
  - 100 days: 1000 points (BADGE)
  - 365 days: 5000 points (BADGE)
- Creates reward with:
  - Type: BADGE
  - Source: STREAK_MILESTONE
  - Title includes milestone days

## 5. Coins System

### 5.1 CoinSource Enum
Tracks coin transaction sources:

- **CHALLENGE_WIN**: Coins from winning challenges
- **CHALLENGE_PARTICIPATION**: Coins from participating
- **DAILY_LOGIN**: Coins from daily login
- **STREAK_MILESTONE**: Coins from streak milestones
- **REFERRAL**: Coins from referrals
- **ACHIEVEMENT**: Coins from achievements
- **ADMIN_GRANT**: Admin-granted coins
- **PURCHASE**: Purchased coins (future feature)
- **REDEMPTION**: Coins spent on reward catalog items
- **OTHER**: Other coin sources

### 5.2 Add Coins
**Function**: `addCoins()`
- Adds or deducts coins from user's account
- Supports positive (earned) and negative (spent) amounts
- Can include expiration date (for time-limited coins)
- Stores metadata, challenge info, and rank (if applicable)
- Returns coin transaction ID

### 5.3 Get Total Coins
**Function**: `getTotalCoins()`
- Calculates user's total available coins
- Only counts non-expired coins
- Sums all coin transactions (positive and negative)

### 5.4 Get Coin History
**Function**: `getCoinHistory()`
- Retrieves coin transaction history for a user
- Supports filtering by source
- Supports pagination
- Sorted by creation date (newest first)
- Shows:
  - Transaction amount (positive/negative)
  - Source
  - Description
  - Challenge info (if applicable)
  - Expiration date (if applicable)
  - Creation timestamp

### 5.5 Get Coin by ID
**Function**: `getCoinById()`
- Retrieves a specific coin transaction by ID
- Returns full transaction details

## 6. Reward Catalog System

### 6.1 RewardCatalogType Enum
Defines catalog item types:

- **PHYSICAL**: Physical products requiring shipping
  - Requires: recipientName, shippingAddress, city, state, postalCode, country
- **DIGITAL**: Digital rewards (vouchers, codes, etc.)
  - Requires: recipientName, recipientEmail OR recipientPhone

### 6.2 Create Reward Catalog Item
**Function**: `createRewardCatalogItem()`
- Creates a new item in the reward catalog
- Fields:
  - Title and description
  - Category (optional)
  - Reward type (PHYSICAL/DIGITAL)
  - Coin price
  - Image URL (optional)
  - Stock quantity (-1 for unlimited)
  - Active status
  - Metadata (JSON)

### 6.3 Get Active Reward Catalog
**Function**: `getActiveRewardCatalog()`
- Retrieves all active catalog items
- Supports filtering by category
- Sorted by creation date (newest first)
- Only returns items with `isActive = true`

### 6.4 Get Reward Catalog Item by ID
**Function**: `getRewardCatalogById()`
- Retrieves a specific catalog item by ID
- Returns full item details including stock status

### 6.5 Update Reward Catalog Stock
**Function**: `updateRewardCatalogStock()`
- Updates stock quantity for a catalog item
- Supports increment/decrement
- Unlimited items (stock = -1) are not updated
- Stock cannot go below 0

## 7. Transaction Management

### 7.1 TransactionStatus Enum
Order/transaction statuses:

- **PENDING**: Order placed, waiting to be processed
- **PROCESSING**: Order is being prepared
- **SHIPPED**: Order has been shipped (includes tracking number)
- **DELIVERED**: Order has been delivered
- **CANCELLED**: Order was cancelled

### 7.2 Claim Reward Catalog Item
**Function**: `claimRewardCatalog()`
- User claims a reward from the catalog
- Process:
  1. Validates catalog item exists and is active
  2. Validates required fields based on reward type (PHYSICAL/DIGITAL)
  3. Checks stock availability
  4. Verifies user has sufficient coins
  5. Deducts coins from user account (creates negative coin transaction)
  6. Creates transaction record
  7. Updates stock quantity (if not unlimited)
  8. Returns transaction details and remaining coins

**Validation Rules**:
- PHYSICAL rewards: Requires shippingAddress
- DIGITAL rewards: Requires recipientEmail OR recipientPhone
- Stock must be available (unless unlimited)
- User must have enough coins

### 7.3 Create Transaction
**Function**: `createTransaction()`
- Creates a new transaction/order record
- Generates unique transaction number: `TXN-{timestamp}-{userId}`
- Stores:
  - User ID
  - Reward catalog ID and title snapshot
  - Coin price snapshot
  - Recipient information
  - Shipping information (for PHYSICAL)
  - Status: PENDING
  - Creation timestamp

### 7.4 Get User Transactions
**Function**: `getUserTransactions()`
- Retrieves all transactions for a user
- Supports pagination
- Sorted by creation date (newest first)
- Returns full transaction details including status

### 7.5 Get All Transactions (Admin)
**Function**: `getAllTransactions()`
- Retrieves all transactions across all users
- Supports filtering by status
- Supports pagination
- Used for admin order management

### 7.6 Get Transaction by ID
**Function**: `getTransactionById()`
- Retrieves a specific transaction by ID
- Returns full transaction details

### 7.7 Update Transaction Status (Admin)
**Function**: `updateTransactionStatus()`
- Updates transaction status (admin only)
- Can update:
  - Status
  - Admin notes
  - Tracking number
- Automatically sets:
  - `shippedAt` when status changes to SHIPPED
  - `deliveredAt` when status changes to DELIVERED
- Updates `updatedAt` timestamp

## 8. API Endpoints

### 8.1 User Reward Endpoints

#### GET `/api/rewards`
- Get all rewards for authenticated user
- Query params:
  - `type`: Filter by reward type
  - `source`: Filter by reward source
  - `claimed`: Filter by claimed status (true/false)
  - `limit`: Limit results
  - `offset`: Pagination offset
- Returns: `UserRewardsResponse`

#### GET `/api/rewards/summary`
- Get reward summary for authenticated user
- Returns: `RewardSummary`

#### POST `/api/rewards/claim`
- Claim a reward (mark as claimed)
- Body: `{ "rewardId": 1 }`
- Returns: `ClaimRewardResponse`

#### POST `/api/rewards/create`
- Create a new reward (users can only create for themselves - typically for testing)
- Body: `CreateRewardRequest`
- Returns: `Reward`
- **Note**: In production, rewards should be system-generated only. This endpoint is primarily for development/testing purposes.

#### POST `/api/rewards/challenge/award`
- Award rewards for challenge winners
- Body: `{ "challengeId": 1, "topNRanks": 3 }`
- Returns: `AwardChallengeRewardsResponse`

#### GET `/api/rewards/challenge/{challengeId}`
- Get all rewards for a specific challenge
- Returns: List of rewards

### 8.2 Coins Endpoints

#### GET `/api/rewards/coins`
- Get total coins and coin history
- Query params:
  - `source`: Filter by coin source
  - `limit`: Limit history entries
  - `offset`: Pagination offset
- Returns: `CoinsResponse`

#### POST `/api/rewards/coins/add`
- Add coins to user's account
- Body: `AddCoinsRequest`
- Returns: `Coin`

### 8.3 Reward Catalog Endpoints

#### GET `/api/rewards/catalog`
- Get all active reward catalog items
- Query params:
  - `category`: Filter by category
- Returns: List of `RewardCatalogItem`

#### GET `/api/rewards/catalog/{catalogId}`
- Get a specific reward catalog item
- Returns: `RewardCatalogItem`

#### POST `/api/rewards/catalog/claim`
- Claim a reward from catalog (create transaction)
- Body: `ClaimRewardCatalogRequest`
- Returns: `ClaimRewardCatalogResponse`

### 8.5 Admin Reward Catalog Endpoints

#### GET `/api/admin/catalog`
- Get all reward catalog items (admin view)
- Query params:
  - `category`: Filter by category
- Returns: List of `RewardCatalogItem`

#### GET `/api/admin/catalog/{id}`
- Get a specific reward catalog item (admin view)
- Returns: `RewardCatalogItem`

#### POST `/api/admin/catalog`
- **Create a new reward catalog item (Admin only)**
- Body: `CreateRewardCatalogRequest`
- Returns: `RewardCatalogItem`
- **Note**: This is the only way admins can create reward-related items. Admins cannot create direct rewards for users.

### 8.4 Transaction Endpoints

#### GET `/api/rewards/transactions`
- Get user's transaction history
- Query params:
  - `limit`: Limit results
  - `offset`: Pagination offset
- Returns: List of `Transaction`

#### GET `/api/rewards/transactions/{transactionId}`
- Get a specific transaction
- Returns: `Transaction`

### 8.6 Admin Transaction Endpoints

#### GET `/api/admin/transactions`
- Get all transactions across all users (Admin only)
- Query params:
  - `status`: Filter by transaction status
  - `limit`: Limit results
  - `offset`: Pagination offset
- Returns: List of `Transaction`

#### GET `/api/admin/transactions/{id}`
- Get a specific transaction (Admin only)
- Returns: `Transaction`

#### PUT `/api/admin/transactions/{id}/status`
- Update transaction status (Admin only)
- Body: `UpdateTransactionStatusRequest`
- Returns: `Transaction`

## 9. Database Schema

### 9.1 Rewards Table
- `id`: Primary key
- `user_id`: User who earned the reward
- `type`: Reward type (POINTS, BADGE, etc.)
- `reward_source`: Source (CHALLENGE_WIN, DAILY_LOGIN, etc.)
- `title`: Reward title
- `description`: Optional description
- `amount`: Point value or quantity
- `metadata`: JSON string for additional data
- `challenge_id`: Associated challenge (if applicable)
- `challenge_title`: Challenge title snapshot
- `rank`: Rank achieved (if from challenge)
- `earned_at`: When reward was earned
- `is_claimed`: Claimed status
- `claimed_at`: When reward was claimed

**Indexes**:
- `user_id`
- `type`
- `reward_source`
- `challenge_id`
- Composite: `(user_id, type)`
- Composite: `(user_id, reward_source)`
- Composite: `(user_id, is_claimed)`

### 9.2 Coins Table
- `id`: Primary key
- `user_id`: User who owns the coins
- `amount`: Positive (earned) or negative (spent)
- `coin_source`: Source of coins
- `description`: Optional description
- `challenge_id`: Associated challenge (if applicable)
- `challenge_title`: Challenge title snapshot
- `rank`: Rank achieved (if from challenge)
- `metadata`: JSON string for additional data
- `expires_at`: Expiration date (null = never expires)
- `created_at`: Transaction timestamp

**Indexes**:
- `user_id`
- `coin_source`
- `challenge_id`
- `expires_at`
- Composite: `(user_id, coin_source)`
- Composite: `(user_id, created_at)`
- Composite: `(user_id, challenge_id)`
- Composite: `(user_id, expires_at)`

### 9.3 Reward Catalog Table
- `id`: Primary key
- `title`: Item title
- `description`: Optional description
- `category`: Item category
- `reward_type`: PHYSICAL or DIGITAL
- `coin_price`: Price in coins
- `image_url`: Product image URL
- `stock_quantity`: Available quantity (-1 = unlimited)
- `is_active`: Active status
- `metadata`: JSON string for additional data
- `created_at`: Creation timestamp
- `updated_at`: Last update timestamp

**Indexes**:
- `category`
- `is_active`
- `reward_type`

### 9.4 Transactions Table
- `id`: Primary key
- `user_id`: User who claimed the reward
- `reward_catalog_id`: Foreign key to reward catalog
- `reward_title`: Snapshot of reward title at purchase
- `coin_price`: Snapshot of price at purchase
- `status`: Transaction status (PENDING, PROCESSING, etc.)
- `transaction_number`: Unique transaction identifier
- `recipient_name`: Recipient name
- `recipient_phone`: Recipient phone (optional)
- `recipient_email`: Recipient email (optional)
- `shipping_address`: Full shipping address (for PHYSICAL)
- `city`: City
- `state`: State/Province
- `postal_code`: Postal/ZIP code
- `country`: Country
- `admin_notes`: Admin notes
- `tracking_number`: Shipping tracking number
- `shipped_at`: When order was shipped
- `delivered_at`: When order was delivered
- `created_at`: Order creation timestamp
- `updated_at`: Last update timestamp

**Indexes**:
- `user_id`
- `status`
- `reward_catalog_id`
- `transaction_number` (unique)
- Composite: `(user_id, created_at)`

## 10. Business Logic & Rules

### 10.1 Reward Awarding Rules

1. **Challenge Rewards**:
   - Only awarded to participants who have submitted stats
   - Rank-based rewards prevent duplicates
   - Participation rewards are one-time per challenge

2. **Daily Login Rewards**:
   - Awarded on each login
   - Streak-based bonus points

3. **Streak Milestones**:
   - Only awarded once per milestone
   - Badge type rewards for major milestones

### 10.2 Coin Management Rules

1. **Coin Expiration**:
   - Only non-expired coins count toward total
   - Expired coins remain in history but don't affect balance

2. **Coin Deduction**:
   - Negative coin transactions are created when spending
   - Total coins calculation includes both positive and negative amounts

3. **Stock Management**:
   - Unlimited items (stock = -1) never go out of stock
   - Stock is decremented when item is claimed
   - Stock cannot go below 0

### 10.3 Transaction Rules

1. **Validation**:
   - PHYSICAL rewards require complete shipping address
   - DIGITAL rewards require email or phone
   - User must have sufficient coins
   - Item must be active and in stock

2. **Status Flow**:
   - PENDING → PROCESSING → SHIPPED → DELIVERED
   - Can be cancelled at any time before DELIVERED
   - Tracking number required when status changes to SHIPPED

3. **Data Snapshots**:
   - Reward title and price are snapshotted at purchase time
   - Ensures historical accuracy even if catalog item changes

### 11.2 User System Integration
- User authentication required for all reward operations
- User ID links rewards, coins, and transactions

### 11.3 Admin System Integration

## Summary

The reward system provides a comprehensive gamification platform with:
- ✅ Multiple reward types (Points, Badges, Coupons, Trophies)
- ✅ Multiple reward sources (Challenges, Daily Login, Streaks, etc.)
- ✅ **System-generated rewards only** - Rewards are automatically created based on user activities
- ✅ Coin-based currency system with expiration support
- ✅ Reward catalog for redemption (admin-managed)
- ✅ Transaction management for order fulfillment
- ✅ Challenge integration for automatic reward distribution
- ✅ Complete API endpoints for all operations
- ✅ Robust database schema with proper indexing
- ✅ Business logic for reward awarding and validation
- ✅ **Admin capabilities**: Can create/manage reward catalog items and manage transactions, but **cannot create direct rewards for users**

### Important Distinction:
- **Reward Catalog Items**: Created by admins - these are products/rewards that users can redeem with coins
- **User Rewards**: System-generated only - automatically created when users complete challenges, log in daily, reach milestones, etc.
- **Admin Role**: Admins can view all rewards (read-only) but cannot create, update, or delete user rewards. They can only manage the reward catalog and transaction fulfillment.

This system enables full reward lifecycle management from earning to redemption, with proper tracking, validation, and fulfillment capabilities.
